# Swap Prism 0.21.1: recuperar audio original

El usuario confirmó que 0.21 dejó mudos todos los impactos de pelota y poste.
Se retiró la prueba. Tras confirmar que Rocket League estaba cerrado se restauró
únicamente SFX_Impacts.bnk con la reversión normal del motor. Hash instalado =
hash original verificado, f7504f104bea32c84a287007376fe9584f6569c761d2ebb2508d6a4b59212d42.
No se cambiaron otros paquetes ni sonidos del juego.

La nueva copia conservaba las rutas y los medios originales, pero rompía dos
condiciones del formato que el lector de grafo no validó:

- Original: 788 entradas DIDX ordenadas, DATA en offset 9520, alineación 16,
  ninguna muestra desalineada.
- Prueba 0.21: 806 entradas DIDX sin ordenar, DATA en offset 9736 (8 mod 16),
  las 806 muestras desalineadas en su dirección absoluta.

Ver work/bank-layout022.json. Es evidencia de un banco defectuoso, no una prueba
individual de todos los motivos por los que el cliente decidió no reproducirlo.
Antes de retomar el aislamiento hay que validar orden/IDs únicos, alineación
ABSOLUTA de DATA + cada offset, y carga/reproducción real. No basta con wwiser,
un decodificador, hashes ni conservar bytes originales dentro de otro contenedor.

La opción de poste queda deshabilitada por audio_manifest.post.disabled_reason.
La UI explica el estado y el motor rechaza aplicarla aunque llegue una petición
directa. El MP3, WAV, volumen y recorte no se borraron: selección archivada en
data/post-recovery-aecba050ed2347b192e700065d6cf1fc.json. El campo activo y el
borrador del poste se retiraron para evitar reinstalar la prueba al cambiar otra
cosa. No se reinstala otra variante de prueba en esta recuperación.

90 pruebas Python / 11 Rust. Se conserva la interfaz y las demás selecciones.
Restauración de archivo confirmada byte a byte; recuperación auditiva tras
reabrir Rocket League todavía requiere confirmación del usuario.
